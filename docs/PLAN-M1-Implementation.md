### Credential vs project errors (D4)

| GitLab response | Interpretation | Action |
|-----------------|----------------|--------|
| **401** (on GitLab API with user PAT) | PAT expired/revoked/invalid | Mark **credential** `invalid`; invalidate membership cache for that user+instance; stop sync with that credential; audit `gitlab_connection_invalid`; **ReviewPulse session stays valid** so user can replace/delete PAT; **do not** treat as single-project deny |
| **403 / 404** on a **specific project** resource | No access / not found for that project | Update **MembershipCache(user, instance, project)** to `allowed=false` (or `uncertain` then fail closed); **do not** invalidate the PAT; PAT must still work for other projects |
| Network / 5xx | Transient | Retry/backoff; membership unchanged unless TTL expired → fail closed on read |

**Test (required):** After 403/404 on Project A, same PAT still successfully reads Project B (membership check + optional sync).

### Failure scenarios

| Scenario | Plan response |
|----------|----------------|
| PAT revoked (401) | Credential invalid; app session kept; user updates PAT in Settings; project reads fail closed until fixed |
| Project A 403, Project B OK | Only A membership denied; B still readable |
| Coalesce dead tokens | Try other enabled users’ credentials; else `sync_blocked`; keep cache |
| GitLab 429 | Backoff; preserve commit/MR cursors |
| SSRF / redirect to metadata IP | Reject egress |
| User A IDOR project B | Authorized-ID set empty for B → 404; no counts/search leak |

## AppAuth & sessions (D8 / D11) — ReviewPulse account ≠ GitLab PAT

### App accounts
- **No public signup.** Admin creates or invites users (`admin` | `tech_lead` | `developer`).
- Login: email + password. Email unique after normalize.
- Password: **Argon2id** hash only — never plaintext or reversible encryption.
- M1: admin password reset; **no** self-serve email reset unless a safe mail provider exists (defer).
- `AppAuthProvider` interface — M1 `LocalPasswordAuthProvider`; future SSO/OIDC.

### Login flow (app)
```
email+password → rate-limit/lockout → verify Argon2id → reject if deactivated
→ create server-side Session (opaque ID to browser; store only token_hash)
→ rotate (new session; revoke prior as policy)
→ Set-Cookie httpOnly; Secure in deploy; SameSite; path=/
→ NEVER accept GitLab PAT as ReviewPulse password
```

### Session policy (locked)
- Storage: PostgreSQL server-side sessions; browser cookie = opaque session id only
- Absolute TTL: **12h** (`SESSION_ABS_TTL_SECONDS=43200`)
- Idle TTL: **2h** (`SESSION_IDLE_TTL_SECONDS=7200`), sliding on authenticated requests
- Rotate session after successful login
- Logout → revoke current session
- Admin deactivate user → revoke **all** sessions for that user
- User/admin **revoke all sessions** action supported
- PAT expiry/401 does **not** revoke ReviewPulse sessions

### CSRF
State-changing routes (login, logout, password change/reset-by-admin, sessions revoke, GitLab connection add/replace/delete/test, project enable/disable, manual sync): CSRF token **and/or** Origin/Referer validation.

### Rate limit / lockout
- Login: e.g. 5/min/IP-hash + temporary lockout after N failures (e.g. 10 fails / 15 min)
- Keys never include password or PAT; no sensitive bodies in logs

### Production
- ReviewPulse served only over **HTTPS** in deploy environments

## GitLab connection (separate Settings flow)

After AppAuth login, user opens **Settings → GitLab**:
1. Enter allowlisted GitLab base URL + personal PAT (`read_api` only in M1)
2. SSRF + HTTPS (deploy) checks
3. `GET /api/v4/user` validates token
4. Bind identity key: **`gitlab_instance_id + gitlab_user_id`** (never email as identity key)
5. Enforce uniqueness: one GitLab identity ↔ one ReviewPulse user (conflicts need admin audited resolution)
6. M1: **one active credential per user per instance**
7. Encrypt PAT (AES-256-GCM, unique nonce/IV, auth tag, key_version); key from env/secret manager only
8. Response/UI: instance, GitLab username, safe hint (last4), connection status, last validated_at, expiry if known — **never** PAT or ciphertext
9. Actions: test connection, replace/rotate token (old → superseded/secure delete), delete connection
10. PAT only in Authorization header — never query string
11. No shared/admin PAT; no using user A’s PAT for user B

### Credential lifecycle
| Event | Effect |
|-------|--------|
| GitLab 401 | Credential `invalid`; invalidate membership caches for user+instance; stop sync with it; prompt update PAT; **app session remains** |
| GitLab 403/404 on one project | Membership deny for that user-project only; PAT stays valid elsewhere |
| Replace PAT | New ciphertext; old superseded; invalidate membership caches; re-validate |
| Delete connection | Remove/secure-wipe credential; invalidate membership; dashboard fail closed for GitLab data; sync_blocked if no other valid credential for coalesce |
| No valid credential for sync | `sync_blocked`; keep cache; do not serve cache without fresh authz; no admin PAT fallback |

### Encryption details
- AES-256-GCM; per-ciphertext nonce; tag; `key_version` in envelope
- Key not in DB, git, or logs; DB backups treated as sensitive
- Wrong key decrypt → safe failure (no partial plaintext)

## Sync strategies (D5, D6)

### Merge Requests
- API: `GET /projects/:id/merge_requests?updated_after=...` (+ pagination)
- Advance `MrSyncState.updated_after_cursor` only after **all pages in the run window** succeed
- Idempotent upsert on `(instance, project_id, iid)`

### Commits (NOT `updated_after`)
GitLab Commits API supports **`since` / `until`** (authored date window), optional `ref_name`.

**M1 ref scope (locked): all non-archived branches**
- Rationale: KPI/activity visibility on feature branches; default-branch-only would miss most WIP commits
- Algorithm:
  1. List branches (`GET .../repository/branches`); skip archived if flagged
  2. For each branch, fetch commits with  
     `since = watermark_authored_at - LOOKBACK_OVERLAP` (default overlap **15 minutes**, env `COMMIT_LOOKBACK_OVERLAP_SECONDS`)  
     `until = now`
  3. Upsert by **SHA** (global per project) — same commit on multiple branches stored once
  4. On mid-page failure: **do not** advance watermark; retry; overlap window recovers boundary/delayed visibility
  5. After **entire** branch set for this window succeeds, advance `watermark_authored_at` to the max authored_at successfully processed minus overlap (or store window end and always re-pull overlap)
- Continuation: persist `last_branch_cursor` if a run hits time/rate budget mid-branch-list
- Rate limits: backoff; never drop watermark on partial failure

**Tests required:** same timestamp boundary; duplicate SHA across branches; failure between pages then retry; watermark not advanced on partial failure.

### Coalesce / credentials
- Unchanged: pick valid credential from users who enabled project; verify readable; 401 → invalidate that credential; 403 on project → membership deny for that user-project only; no admin PAT.

### Read-only
- Client exposes no note/approve/merge methods; CI forbids mutation path strings in M1 packages.

## Membership cache (D6 detail)

- Default TTL: **300 seconds** (`MEMBERSHIP_CACHE_TTL_SECONDS`)
- On hit within TTL with `allowed=true|false`: may use value  
- On miss / expired / GitLab error / uncertain: **fail closed** for reads (no data)

### AI-assisted detection (M1)
- Subject match regex (case-insensitive): token `\[[Aa][Ii]\]` as a bracketed tag  
- Examples **count:** `[AI] refactor module`, `[ai] add tests`, `fix: timeout [AI]`  
- Examples **do not count:** `AI refactor module` (no brackets)  
- Absence of tag ≠ “did not use AI”  
- Dedupe: one count per `(gitlab_instance_id, project_id, sha)`  
- `verification_status: self_reported`; metric key `ai_assisted_commits`  
- Do not edit GitLab commits; no Claude/prompt-tool ingest in M1  

### Commit frequency (M1)
- Display: count in week window + reference 3–8 + source GitLab  
- Dedupe by instance+project+SHA (multi-ref → once)  
- **Human decisions (open — until locked, document assumptions in rule options or keep notes):**  
  - Timezone & week boundary (default proposal: **Asia/Ho_Chi_Minh**, week **Monday 00:00** — mark `assumption` until approved)  
  - Counting set vs sync set: sync = all non-archived branches; **counting uses SHA set authored in window** (same pool) unless company says default-branch-only for KPI  
  - Unmerged commits: **include** (assumption) until decided  
  - Merge commits / bots / reverts: **exclude merge commits & bot authors matching `/bot/i` or GitLab bot flags** (assumption); reverts **include** until decided  
  - Author emails: match against viewer’s `UserEmail.normalized_email` list (verified and unverified may match for *linking*, but UI marks unverified)

## Acceptance criteria (M1)

1. Only admin-created/invited users can login (email+password Argon2id); PAT cannot be used as app password.
2. Sessions: opaque cookie, hashed at rest, 12h abs / 2h idle, rotate on login; logout/deactivate/revoke-all work; PAT 401 does not kill app session.
3. GitLab connection in Settings: allowlisted URL + `read_api` PAT; identity = instance+gitlab_user_id; unique binding; SSRF hardened.
4. PAT encrypted (nonce+tag+key_version); never in API/UI/logs/audit; admin cannot view plaintext PAT; replace/delete works.
5. CSRF/Origin on all state-changing routes; rate-limit/lockout without logging secrets.
6. Enable only GitLab-visible ∩ allowlist; per-user; no peer grant.
7. MR sync via `updated_after`; commit sync via `since`/`until` + overlap + all non-archived branches; SHA upsert; cursors advance only after full successful window.
8. 401 invalidates credential; 403/404 on A does not break B.
9. Dual authz; IDOR tests (direct id, search, count, export if any).
10. Membership expiry fail closed; no stale allowed=true.
11. Dashboard deep links; mismatch/warn without claiming unverified alias = confirmed KPI.
12. No KPI score/grade/pass/fail/verdict; no prompt inference; no Claude Members.
13. Commit frequency + AI-assisted reference metrics with required provenance fields; `[AI]` detection per FR-K4.
14. LOC/MR-size return `not_configured` (or locked trivial stats only); no fail coercion.
15. No GitLab mutations.
16. Audit without secrets; CI green including new KPI-reference tests.
13. Audit without secrets.
14. CI green for unit/integration/security/E2E listed in test plan.
